\section{Introduction}

Digital signatures are essential for proving the authenticity, integrity and non-repudiation of documents. They guarantee that a specific record was processed by a notary and that it has not sustained any modification since being signed. \\\\
However if a system solely relied on digital signatures, a malicious actor could silently delete a previously notarized document, reorder historycal transactions or present an incomplete version of the events to an auditor which would not detect any related issues since the signatures of the individual document would still be mathematically valid.\\\\
To prevent this, a notary requires a notary requires an ordered log which enables tamper detection. By structuring recepits into a caryptographic hash chain, each new notary operation is linked to the previous one, thus creating an immutable sequence. Any attempt to remove, reorder, alter past events will inevitably cause incoherence in the chain, which is detectable by the system. Thus \textbf{digital signatures} are needed to ensure fine-grained validity of a document, while the \textbf{hash chain} operates at a coarse-grained level.

\subsection{Goals}
The main goal of this project is to simulate and analize a central notary authority that processes document signing requests. The system includes a performance simulation component that models the signing authority as a single-server queue, allowing for empirical observation of queueing metrics and comparison against theoretical models such as M/M/1 and M/G/1.

\section{Background}

\subsection{Digital signatures}
Digital signatures ensure the authenticity, non-repudiation and integrity of digital documents. The central notary authority supports two asymmetric cryptographic algorithms: the Elliptic Curve Digital Signature Algorithm (\textit{ECDSA}) using the P-256 curve, and the RSA algorithm with the Probabilistic Signature Scheme (\textit{RSA-PSS}) using a 4096-bit modulus.
\\When a document digest is submitted, the authority signs it with its private key, generating a signature that is verifiable by anyone using the corresponding public key.

\subsection{Hash chains and tamper evidence}
To ensure the immutability of the \emph{audit log}, the system structures recepits into a \textit{hash chain}. Each new recepit computes a \texttt{chainHash} using the SHA-256 hash function over the previous block's hash \texttt{prevHash}, the current block's \texttt{signature} and the \texttt{docDigest}; thus forming a sequential dependency which guarantees the propagation of any tampering attempt made on any past block invalidating every subsequent one.
\\\\
The logical structure of the afore mentioned blocks can be visualized as follows:
\begin{equation}
  h_i = \mathrm{SHA\text{-}256}\bigl(h_{i-1} \,\Vert\, \sigma_i \,\Vert\, d_i\bigr),
  \qquad h_0 = 0^{256},
  \label{eq:chain}
\end{equation}
where $d_i$ is the document digest and $\sigma_i$ its signature.
\\\\
If an attacker modifies the contents of entry $j$, for example altering the document digest, the output of the hash function for that block changes entirely due to the avalanche effect, resulting in a new hash $h'_j$ \neq $h_j$. Because the next block's hash, $h_{(j+1)}$ depends on $h_j$, computing $H(h'_j \parallel \text{data}_{j+1})$ will yield a different result, $h'_{(j+1)}$. By induction this cascades forward indefinitely.


\subsection{Queueing model}
The system evaluates performance using queueing theory, modelling the authority as a single-server queue with Poisson arrivals. Two analytical models are tracked to predict queue waiting times ($W_q$):
\begin{itemize}
  \item{\textbf{M/M/1}}: assumes both exponential inter-arrival times and exponential service times
\end{itemize}





Requests arrive as a Poisson process of rate $\lambda$, so inter-arrival times are
exponential; they are generated by inverse transform sampling,
$\Delta t = -\ln(1-U)/\lambda$ with $U\sim\mathcal{U}(0,1)$.
A single worker serves them in FIFO order with a general service-time distribution,
i.e.\ an M/G/1 queue. With $\rho = \lambda\,\mathbb{E}[S] < 1$ the
Pollaczek--Khinchine formula gives the mean waiting time
\begin{equation}
  \mathbb{E}[W_q] = \frac{\lambda\,\mathbb{E}[S^2]}{2\,(1-\rho)},
  \qquad \mathbb{E}[S^2] = \mathrm{Var}(S) + \mathbb{E}[S]^2 .
  \label{eq:pk}
\end{equation}

\begin{itemize}
  \item the chain hash covers signature and digest but \emph{not} sequence, timestamp
        or algorithm, so those fields can be altered undetected;
  \item the log lives in the client's memory, so an attacker can rewrite it \emph{and}

  \item keys are generated with \texttt{extractable: true}, which is stricter as
        \texttt{false} for the private keys;
  \item a single central authority is a single point of trust and of failure;
